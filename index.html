03

Analysis mode & data source

One website, three ways of reading the market. The active mode is always visible.

Mode
Demo is selected by default. Nothing is presented as live until a feed proves it.

Mode A — MT5 broker feed REQUIRES A RUNNING BACKEND

This website is static: GitHub Pages cannot hold a MetaTrader 5 connection. Live XAUUSD data comes from backend/mt5_server.py running on a Windows machine (or VPS) where your MT5 terminal is installed and logged in. The browser only ever calls read-only endpoints — there is no trading function anywhere in this project. Broker symbol names differ (XAUUSD, XAUUSDm, GOLD), so the backend reads whatever symbol you configure and reports it back.

Not connected. Live prices are not displayed until a backend answers and its data passes validation.

Endpoints provided by the backend

GET /api/healthterminal and symbol reachability
GET /api/market/statusconnection, spread, bid/ask
GET /api/market/pricecurrent tick
GET /api/market/candles?symbol=XAUUSD&timeframe=M15&limit=500
GET /api/market/symbol-infocontract size, tick value, tick size

Credentials live in environment variables on that machine only (MT5_LOGIN, MT5_PASSWORD, MT5_SERVER) — never in this page and never in a public repository. If your backend is on another machine, GitHub Pages will call it over HTTPS and the backend must allow your site's origin (ALLOWED_ORIGIN). Free hosting rarely permits continuous operation, so expect the status to read OFFLINE or NOT CONNECTED outside the hours your machine is running.

Why automated screenshot reading is not active here

Genuine image analysis needs a vision model or a backend service: an upload button on its own is not analysis, and inventing readings from an image would be dishonest. Until such a provider is configured, the panel reports IMAGE ANALYSIS BACKEND NOT CONFIGURED and the manual fallback records only what you can actually see.

To enable it later, implement window.KP56ImageAnalysisProvider (the contract is documented at the top of screenshot-analyser.js) pointing at your own vision service, and tick the consent box so the disclosure is explicit before anything is transmitted. Your screenshots are never sent anywhere in this phase — they stay inside your browser.

10

Telegram alerts

Interface only. No bot token is requested, stored or transmitted.

NOT CONNECTED

Real Telegram messaging requires a running backend (Phase 2 or later). Credentials must live on that server — never in this page, and never in browser localStorage.

What will be wired up later

  1. Phase 2 — a small Python backend holds the bot token as an environment variable and calls the Telegram Bot API from the server side.
  2. Phase 2 — this page posts {symbol, direction, entry, sl, tp1, tp2} to that backend over HTTPS; the backend decides whether to send.
  3. Phase 3 — cooldown, duplicate-signal protection and delivery logging live on the server so they keep working when your phone is offline.
  4. Phase 1 (now) — only the preference controls are real, and they are stored locally as non-sensitive UI settings.

Preference switches in Phase 1 are stored in your browser only and are not transmitted anywhere.
